## 4. 本轮新发现问题

### F1（medium）两个已注册的浏览器验收脚本与现路由脱节，其中一个被 `019baae` 直接打断

**调用链**：

```
router.ts:114    const query = isInternalPath(to.fullPath) ? { return: to.fullPath } : {}
router.ts:119    typeof ret === 'string' && isInternalPath(ret) ? ret : defaultEntry(...)
LoginPage.vue:40 const target = ... isInternalPath(ret) ? ret : '/'
```

`019baae` 删除白名单分支后，`isInternalPath` 只剩基础正则 `^\/(?!\/)[A-Za-z0-9\-._~/]*$`，该正则**不接受 `?`**。因此匿名访问 `/student/home?design=a` 时 `to.fullPath`（含查询串）不再写入 `return`，登录后回落到 `defaultEntry` → `/student/home`（无参数）。

**受影响脚本**：

| 脚本 | 断言 | 状态 |
| --- | --- | --- |
| `frontend/scripts/verify-home-exploration.mjs:18`<br>（`npm run test:browser:home-design`） | `assert.ok(page.url().endsWith('/student/home?design=a'), 'login must restore selected design')` | **必然失败** |
| `frontend/scripts/verify-home-bplus.mjs:51`<br>（`npm run test:browser:home-bplus`） | `design('a')` 后断言 `[data-design=a]` 存在；`design('current')` 后断言 `.dashboard-page` 存在 | **早已不成立**（与本次改动无关的既有漂移） |

**结构性证据**（标记出现次数）：

| 标记 | 生产 `visual/StudentHome.vue` | 演示 `dashboard/StudentHomePage.vue` |
| --- | --- | --- |
| `data-design` | 1（硬编码 `bplus`） | 0 |
| `dashboard-page` | 0 | 1 |
| `explore-focus` | 4 | 0 |
| `bplus-group-heading` | 1 | 0 |
| `bplus-task-group` / `bplus-task-list` / `bplus-course-action` | 有 | 无 |

即：生产首页是固定的 B+ 结构，不含预览切换器，`design('a')` / `design('current')` 无法改变其呈现。

**为何 CI 未报警**：

```
verify = npm run typecheck && npm run build && npm run check:no-mock && npm run test
```

不含任何 `test:browser:*` 脚本，浏览器验收属手动执行。

**为何值得处理**：AGENTS.md §3 规定"已完成/已同步不算证据，要有命令输出"。当前 `frontend/README.md:27` 仍把 `npm run test:browser:home-design` 列为可用检查，执行者会得到失败结果，进而要么怀疑自身环境，要么不再信任这套脚本。

**建议**（二选一）：

1. 把两个脚本的目标改为 campus 演示入口——那是 `design` 参数目前唯一的消费者；或
2. 删除脚本中针对 `design` 的断言，仅保留生产首页结构断言，并在 README 标注脚本适用范围。

## 5. 本审计的误判记录（第 3 轮 R2 / nit2）

### R2：把 `dashboard/StudentHomePage.vue` 误判为生产首页渲染器

**误判依据**：读到 `dashboard/StudentHomePage.vue` 中 `design` 默认 `'bplus'`、`v-if="design!=='current'"` 渲染 `HomeExploration`，据此断定它是生产首页渲染器。**未核对路由映射即下结论**。

**实际情况**：

```
router.ts:22   import StudentHomePage from '../features/student/visual/StudentHome.vue'
router.ts:70   { path: '/student/home', component: StudentHomePage, ... }
```

局部标识符名为 `StudentHomePage`，但导入的是 `visual/StudentHome.vue`——**同名不同文件**。`dashboard/StudentHomePage.vue` 仅被三处引用：

| 引用位置 | 用途 |
| --- | --- |
| `demo/campus/visual/install-integration.ts:7` | campus 演示 |
| `demo/campus/start.ts:38` | campus 演示路由表 |
| `tests/p1d-ui.test.ts:6` | 单元测试 |

**教训**：本仓库 `router.ts` 的 import 别名与真实文件名不一致。凡判断"谁是生产组件"，必须先读路由表，再读组件，不能由命名或局部变量推断。

### nit2：§4 竞态数量

误判表述为"AI 相关只有 3 类"。实际 §4 共 5 行：归档与提交、写入后归档（归属类 2 条）、AI 并发、AI 响应丢失（AI 类 2 条）、死锁与锁等待（1 条）。`§0` 写"5 个"准确。
