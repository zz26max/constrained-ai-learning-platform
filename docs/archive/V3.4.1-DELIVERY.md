## 2. 问题、精修与取舍

| 证据与位置 | 处理 | 理由与结果 |
| --- | --- | --- |
| V3.4 Java记录当前章同时出现节点、边框、侧线和背景强调 | 32px桌面/28px手机节点；当前实心节点配轻底侧线，取消整圈蓝框及重阴影 | 保留当前章识别，减少同状态重复。已读仍有文字与复习入口 |
| 记录标题和成果区重复品牌表达，分数夺目 | 使用章节学习路径、课程学习概览、教师反馈；只留一次短句；分数中性色 | 标题先说明功能，真实反馈和分数保留 |
| 单章路径与空记录在宽屏形成不合理比例 | 单章路径占一行，成果随后两列；零章改紧凑说明行 | 不填充假节点。零章初次全宽大空盒在截图审阅中被否决，最终采用图形/说明/目录操作的紧凑行 |
| 课程90px书脊与竖排分类占据内容空间，多个蓝色操作争夺注意 | 桌面书脊68px，分类移至正文顶行；数量/百分比归一行，操作与位置降低彩色权重 | 保留学科图形、色与标题；正文和点击区域不缩小。手机图形仍保留 |
| 固定截断分段不适用于大量章节 | ≤12章按真实数量分段，>12章改连续比例轨道并保留真实计数 | 不把20段误读成全部章节；分段始终只表达阅读数量 |
| 日历近似密度色阶难区分，今天与选中竞争 | 使用显式数量，3项以上仅浅中性底；今天下划线、选中蓝底，二者可共存 | 不依赖细微色差理解任务数 |
| 10月24日三任务同为18:00却重复时间 | 精确截止时刻分组，一次时间标题、三条独立任务 | 不合并任务ID、状态或详情入口；等价时区归同组 |
| 日期与处理状态不能独立证明可提交 | 仅精修版读取选中日作业详情，显示实际资格；失败保持未知并允许重试 | ≤6并发，无新字段/接口。最终仍由作业详情与提交校验决定 |

章节动作使用已发布章节的实际阅读状态：completed→复习，in_progress→继续，not_started→开始；进度缺失→查看，未发布→不可访问。列表不制造尚未开放的未来节点，不创造 canRead 等契约字段；既有章节内容页、归档只读与业务校验保持原行为。
