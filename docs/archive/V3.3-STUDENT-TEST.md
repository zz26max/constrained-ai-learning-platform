# 知学 V3.3 学生体验测试材料

本文件是待执行的测试材料，不包含真实参与者结果。建议招募 3–5 名首次使用知学的大学生，每人约 20–30 分钟；至少分别覆盖桌面与手机。征得同意后才录屏，用 P01–P05 代号记录，不记录姓名、学号或真实课程数据。

## 主持人准备

1. 在项目根目录运行 `npm --prefix frontend run dev:campus`，打开 `http://127.0.0.1:4174/campus.html#/student/home`。同一台电脑可用桌面浏览器和手机尺寸模拟；这不能替代手机真机测试。服务默认仅绑定本机，不向局域网开放。
2. 确认顶部“高校演示 · 虚构数据”，日期固定为北京时间 2026-10-19 10:00。为每位参与者刷新页面，清除上一次演示状态。不要打开正式端 4173。
3. 先执行首页 3 秒测试，再解释页面功能。每个任务开始前刷新重置，并回到任务指定起点；任务内跳转、浏览器后退和菜单切换可以保留内存状态。不要在任务中途刷新。
4. 计时从读完任务并允许操作开始，到满足完成标准为止；遇到错误继续计时。超过 3 分钟可询问是否放弃，统一记录“超时”，不要代替学生完成。
5. 错误定义：进入无关页面、选择错误任务、误触、尝试禁用操作。明确帮助、提示、返回次数分别记录，不把探索性查看自动算成错误。任何主持人提示后完成的任务记为“辅助完成”。

## 给参与者的说明（可直接朗读）

“我们在测试平台是否容易使用，不是在考核你的能力。所有课程、姓名和作业都是虚构的。保存、提交和标为已读只影响当前预览，刷新会重置。请按任务操作，并说出你的想法；不确定时也可以直接告诉我。你可以随时停止。这里的提交不会发送给真实教师。”

## 首页 3 秒定位

先短暂展示首页 3 秒，再遮挡页面，请参与者回答：“你觉得下一步可以做什么？你刚才会点哪里？”不预先告知主按钮位置，不用自动化脚本的点击速度代替学生定位时间。

记录：参与者＿＿　设备＿＿　辨认的任务＿＿　指认入口＿＿　是否为可操作任务＿＿　是否误以为逾期任务不可补交＿＿　原话＿＿

首页现有主任务是允许补交的网络任务，近期列表还有今天 18:00 截止的 Java 任务。两者都可操作；将学生的选择及原因分别记录，不擅自规定补交一定比今天截止更重要。

## 结束提问

1. 首页哪个信息最能帮助你决定下一步？补交任务和今天截止的任务，你会优先做哪一个，为什么？
2. “2/4 已开放章节已阅读”和“100%”各是什么意思？是否意味着已经掌握整门课程？
3. 查找最近截止作业时，最困惑的地方是什么？你如何判断还能不能提交？
4. 教师反馈容易找到吗？你是否能区分正在编辑的工作区与已经提交的版本？
5. 日历的月、周、手机日期条是否符合习惯？你如何找到没有显示在本周的任务？
6. 手机上哪些按钮容易误触？有没有不知道自己在哪、如何返回的时候？
7. 哪一项最希望改善？各任务易用程度请按 1（很难）–7（很容易）评分，并说明原因。
