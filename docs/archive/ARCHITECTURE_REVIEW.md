# 项目架构与前后端设计评审记录

版本：0.3 · 日期：2026-10-03 · 状态：设计评审修订，尚未实现。

## 1. 评审结论

**采用项目已确定的 Spring Boot + MySQL 模块化单体，并接入现有原生 HTML/CSS/JavaScript 前端。** 该技术栈适合当前课程项目规模。保留 API、服务层和数据访问层的职责划分，按 P0/P1 教学闭环、P2 受限 AI 与分析、P3 隔离检查推进。当前没有引入微服务、Redis 或额外消息中间件的必要。

本轮修订补齐并发边界、接口与页面缺口、证据语义和数据生命周期，可以据此开始分阶段实施。评审通过的是设计方向与修订决策；后端尚未实现，不能据此宣称安全验证、并发测试或真实前后端联调已通过。

落地文档：[开发方案](../DEVELOPMENT.md) · [接口契约](../API.md) · [数据模型](../DATA_MODEL.md) · [前端接入方案](../DEVELOPMENT.md#10-前端接入方案)。本记录解释重要决策；开发时以配套文档中的字段、状态和事务契约为准，发现冲突应先同步修订。

v0.3 核对项目既定技术栈，纠正 v0.2 中“开发语言未指定”的错误假设；已按 MySQL/InnoDB 重写存储与事务设计。当前目录没有后端工程，无法由现有代码判定框架实现质量；此前改用 Python 的建议没有项目依据。

## 3. 学习分析口径

- P2 首版（knowledge-v2 规则）的掌握证据只来自教师已发布的明确知识评价。客户端行为、AI 推测和学生求助标签不能替代教师证据；P3 加入可信检查时另行发布规则版本。
- `learning` 只用于存在关联进行中任务的情形，并服从已有明确教师结论的优先级。只有一次历史 `meets_expectation` 且无进行中任务时，返回 `insufficient_evidence`，说明“已有一次符合要求记录，尚不足以形成综合判断”。
- 返回 `latestEvidenceAt`、`evidenceCount`、`freshness`。最近证据距计算时刻不超过 90 天为 `fresh`，超过 90 天为 `stale`，无证据为 `none`；90 天是展示口径，不是科学验证的遗忘周期。`asOf` 仅为计算时刻。
- 历史“基本掌握”必须同时显示证据时间。`stale` 不抹掉教师结论，但不能把它描述或推荐为当前测量结果；建议解释应明确依据的时间范围。
- 共性问题分别返回 `reportedStudentCount`、`confirmedStudentCount`、`distinctStudentCount`。前者是自报求助，确认人数来自教师或已纳入规则的可信检查；总人数按学生取并集，不能直接相加。
- 活跃时长先按同一用户、会话、课程与活动目标形成有效相邻心跳区间，再在所需统计范围内取并集。不跨会话连接单个心跳；离线空档不补齐，结果始终标为客户端报告的“估计活跃时长”。

## 4. 设计验证范围

本轮按页面需求、API DTO、持久实体和事务边界相互对照，明确角色与对象权限、空态/失败态、不可变提交和公开反馈，以及 P1/P2/P3 的能力边界。文档一致性检查包括链接、字段/枚举、示例和同一规则在不同文档中的表述。

这些工作不能替代真实实现测试。浏览器预览限制、数据库锁与约束、时区边界、worker 恢复、模型输出约束和数据清理，必须在相应阶段以可复现案例验证；未实现功能不得用演示值表示验收通过。

预览边界核对依据：[MDN iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe) 与 [MDN CSP default-src](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/default-src)。`default-src` 是资源获取指令的回退，sandbox 的顶层导航限制不等同于关闭整个浏览器网络。

| 阶段 / 使用范围 | 必须具备的验收证据 |

| P2 受限 AI | 跨会话并发仅一个在途请求、预算不超额、政策更新可阻断旧输出、未知外部结果不重复生成；覆盖各调用阶段崩溃、租约接管与旧 worker 迟到，结果最终进入可解释终态。 |
| P2 分析与保留 | 使用可控时间核对单份历史证据、陈旧证据、无证据、重复事件、多来源去重、跨会话心跳；验证 90 天正文及副本清理后历史接口仍可解释且考核链完整。 |
| P3 隔离检查 | 在独立环境验证网络、文件系统、CPU/内存、超时与清理；基础设施错误不计学生失败；检查规则与版本可追溯，不把客户端预览当作可信检查。 |

部署、账户导入、真实课程数据保留周期及 AI 提供商配置按开发方案逐项落实。它们不阻塞已有默认方案下的 P0/P1 开发；正式接入真实数据前必须确认适用配置并完成相应验收。
