# 前端审查修复方案

日期：2026-10-26。基线：`ecc6a60`。本文件是给前端负责人的实施与验收方案，尚未实施的项目均保持未勾选。字段、枚举、错误、权限和幂等规则只以 [OpenAPI](../openapi.yaml) 为准；界面与工程规则见 [FRONTEND](../FRONTEND.md)，业务规则见 [DEVELOPMENT](../DEVELOPMENT.md)。本方案不新增接口或改变契约。

## 分工与执行顺序

前端负责 `frontend/` 的生产页面、mock、测试；后端独立修复发布通知标题、输入校验和必要诊断。不要替后端改数据库、放宽权限或在页面编造成功响应。开始前保存现有工作区状态，独立分支开发，保留他人改动。共享 STATUS 及契约文档由当前集成负责人集中维护，避免并行覆盖。

推荐顺序：F1 徽标 → F2 mock 契约 → F3 消息域去重 → F4 请求超时 → F5 事件退出冲刷 → F6 有证据的请求性能优化。每包独立提交并记录实际检查。F1、F2 是本轮优先验收项；F3–F6 分包推进，不要求一次提交完成全部重构。

## F1：生产消息页与全局未读徽标

**已核实的定位**：`app/router.ts` 的 `student-messages` 实际挂载 `features/student/visual/StudentMessages.vue`；徽标 watch 当前位于 `features/notifications/NotificationCenter.vue`。顶栏消费 `stores/notifications.ts`，首页也会向它写入计数。

**实施要求**：

- 将计数更新接入实际生产路由，测试必须挂载生产消息页及顶栏/store，不能只验证 demo 的 NotificationCenter。
- 明确两种计数：当前筛选列表计数与全局徽标计数。后端 `AssignmentService.listMessages` 的 summary 会随 offeringId/type 改变，不随 read/分页改变；不要用筛选后的计数覆盖全局值，也不要数当前页 items。
- 未设置班级/类型筛选时，可复用列表 summary。带筛选时，在初次进入或已读成功后通过既有、不带班级/类型筛选的 listMessages 小分页请求更新全局计数；集中协调去重，顶栏本身继续只展示状态。若选择其他策略，必须证明不会把部分计数当全局计数。
- 仅服务端成功后更新计数。写失败保留原值并显示错误；未知继续为 null，确认没有未读才为 0。已有值刷新失败时不伪装成 0。
- 同时协调首页和消息页写入：请求完成时校验账号及代次，较早的 dashboard 响应不能覆盖较新的已读结果。登出/切账号后清除计数并阻止旧响应写回。

**验收**：

- [ ] 深链进入 `/student/messages`，不先访问首页，也能显示全局未读数。
- [ ] 最后一条未读成功标读后徽标消失；失败时保留原计数。
- [ ] 类型筛选、分页及空筛选结果不会把全局徽标改成局部计数。
- [ ] 旧首页请求迟到、快速筛选、登出再登录另一账号，不发生计数倒退或跨账号污染。
- [ ] 保留顶栏无障碍标签以及已有列表刷新不闪空行为。

## F2：mock 与现行契约对齐

**重点文件**：`mocks/assignments.ts`、`mocks/feedback.ts`、`mocks/tutoring.ts`；优先复用 `tests/p1b-student.test.ts`、`p1b-teacher.test.ts`、`p1d-mocks.test.ts`、`submission-feedback-flow.test.ts`、`learning-events.test.ts` 的夹具与入口。

先按 operationId 使用 contract_slice.py 提取 saveWorkspace、submitAssignment、listMySubmissions、listTeacherSubmissions、saveFeedback、publishFeedback、recordLearningEvents。不要把本方案当第二份错误码规范。

- 同 workspaceRevision 重复提交返回原提交，不新增次数、快照或覆盖 reflection。检查顺序要保留契约允许的归档后重放行为，并核对已达提交上限后的重放；不能仅把 409 改成 200 而仍在前面被拦截。
- 工作区版本冲突使用契约错误与 currentRevision 详情；提交次数限制使用契约登记错误。清除自造错误码，更新依赖旧行为的测试断言。
- 已发布评价在契约允许的前一版本/当前版本重放时返回原视图，不增加版本、通知或知识证据；其他版本仍冲突。
- listMySubmissions 返回完整分页结构；实现 listTeacherSubmissions 的筛选、分页及范围限制，不能仅消除 MockNotImplementedError。
- 校验 activeFile、reflection 的存在性及允许空值，不能把“允许空字符串”误当成“字段可省略”。
- 事件同 ID 同正文计 duplicate；同 ID 不同正文冲突且整批回滚。先校验整批再改 mock 状态，保持已有去重键与用户隔离语义。
- 解除 feedback 与 tutoring 的初始化依赖时，提取无反向业务依赖的状态协作者；不要用新增循环导入连接 mock 模块。

**验收**：

- [ ] 首次提交、原 revision 重放、保存新 revision 后重放旧提交、归档后重放和次数达到上限后的重放符合契约。
- [ ] 发布评价两种合法版本重放均幂等；错误版本冲突且通知数不变。
- [ ] 列表空页、越界页、筛选后 total、完整分页遍历以及跨账号/跨班拒绝有测试。
- [ ] 省略必填字段被拒，契约允许的空值被接受；事件批次失败不会留下部分写入。
- [ ] 真实模式失败仍暴露真实错误，不引入回退 mock 的路径。

## F3：消息域共享逻辑，保留视觉壳

范围为 NotificationCenter、StudentMessages、demo/campus/visual 下 CraftMessages 与 IntegrationMessages 的列表加载、筛选、分页、标读、目标跳转和错误处理。先确认仍存在的引用再迁移。

在 `features/notifications/` 建立共享 composable，向页面提供状态和动作，页面保留不同模板及视觉规则。复用已有 usePageQuery、targetRoute、useMessageOverflow；不要为了此次去重顺带迁移整个 shared 层或批量格式化。

生产入口使用共享实现。demo 保留自己选择的视觉模板，不能从生产模块反向 import demo。将领域行为测试放到共享实现/生产入口，demo 仅保留必要的展示检查。确认无引用及无保留需求后，才另包处理旧页面删除。

**验收**：

- [ ] 四个仍在使用的入口共享同一套消息行为，不再各复制一段 script。
- [ ] F1 的全部测试、help_reply/feedback 跳转、标读失败和账号切换测试通过。
- [ ] 桌面/手机消息页布局与键盘交互保持既有行为；生产构建无 demo/mock 依赖。

## F4：请求截止时间与取消语义

范围：`api/real-transport.ts`，按需调整客户端选项及对应测试。采用统一、可测试的截止时间，初始建议 30 秒；它约束一次 HTTP 请求，不限制 AI 异步任务完成总时长。

- 将页面传入的 AbortSignal 与截止时间结合，覆盖 fetch 和响应 body 读取。确保定时器/事件监听在成功、失败、取消后释放。
- 用户离页或账号变化的主动取消继续作为取消处理，不冒出错误提示；网络截止时间作为可展示的本地传输错误，不能发明后端业务错误码。
- 超时后解除 loading 并可显式重试。尤其是 POST 超时，服务端可能已经成功：不自动重放写请求；按对应操作的幂等或状态查询流程恢复。AI 请求优先找回在途请求，不能盲发第二次产生费用。
- 检查目标浏览器是否支持所选组合信号 API，必要时用小型兼容实现，不增加无关依赖。

**验收**：

- [ ] 请求无响应、响应头已到但 body 卡住，都能在截止时间结束并显示重试入口。
- [ ] 路由取消、换账号取消不显示网络错误；迟到响应不更新页面。
- [ ] 成功/失败后的计时器释放；写请求不自动重试；CSRF 原有恢复规则仍成立。

## F5：学习事件退出冲刷与重试

范围：`features/analytics/reporter.ts`、事件 API 选项及 transport 的最小扩展。保持四类允许事件、现有 eventId 去重与数据最小化。

- 优先在 visibilitychange 进入 hidden 时尝试发送，pagehide 做补充；退出时只用已有 CSRF token，不能等待刷新令牌。
- keepalive 仅对该事件上传路径启用，不对所有请求全局开启；按 UTF-8 字节预算和批次条数共同切分，考虑浏览器 keepalive 在途总预算，不能假设 50 条一定可发送。
- 明确普通 flush 与退出 flush 的队列所有权；已有请求在途时不简单丢弃剩余队列，也不能因同时发送而更换 eventId。成功确认后出队，失败按既有上限重试。
- 若退出时在途批次结果未知，可在后续同账号活跃窗口按原 ID 重试；持久化待发事件会增加本地数据保留策略，若采用须先明确范围、期限、退出清除及账号隔离，不默认写 localStorage。
- 不直接换成 sendBeacon：现有接口要求 Cookie、JSON 和自定义 CSRF 头，必须保留安全约定。没有相应接口设计，不另开无 CSRF 的 beacon 端点。
- 只声明提高尽力投递成功率，不承诺关闭浏览器或断网后的零丢失。

**验收**：

- [ ] 普通 flush 在途时隐藏页面，剩余队列仍按设计处理；多批和字节超限都有测试。
- [ ] 重发保持相同 eventId，不重复统计；失败批次不会静默当成功清空。
- [ ] 无缓存 CSRF、离线、401、退出/换账号均有明确行为，不把旧账号队列送给新账号。
- [ ] 用真实浏览器网络记录核对 keepalive 请求；模拟 fetch 测试不能独自证明卸载期送达。

## F6：测量后优化串行请求

- `use-student-home.ts`：为独立详情请求采用有界并发（可复用“我的作业”页已有实现思想），先记录请求数量与最大并发。单个已失效对象按业务处理并展示部分失败状态；401/会话失效应统一退出，不当作普通缺失吞掉。
- `HelpRequestCreatePage.vue`：会话/消息加载按可见范围懒加载或有界并发，提供继续加载；不能将固定 20 个会话/50 条消息当完整历史。取消选择或切作业时取消旧请求，选中共享内容仍由后端最终校验。
- `StudentAssignments.vue`：以稳定的账号、班级、筛选条件或待办 ID 集合控制加载，避免仅页码/排序改变就全量重取。若加缓存，明确成功提交、归档、账号切换等失效条件及容量；不要用无边界全局 Map。

**验收**：

- [ ] 保存优化前后的请求数/瀑布和数据量条件，不以主观“更快”作为证据。
- [ ] 有界并发上限、分页/排序不重复全量加载、单项失败与取消场景有测试。
- [ ] 不因缓存展示已失效的提交资格、泄漏其他账号数据或声称部分历史是全部历史。

## 本轮不混入的事项

全仓 shared 迁移、所有 DTO 类型重写、全局状态常量化、格式化工具导入及批量旧页面删除另列维护任务。登录学期标签、shallowRef 嵌套修改、断点差异及无消费者 token 可由前端复现后单独小包处理，不与 F1/F2 绑成大提交。公告是否允许 help_request 目标须按具体操作约束核对，前端不得仅按共享 TargetDTO 枚举放宽或修改后端契约。

## 交付证据

每包提供改动文件、生产入口、契约 operationId、测试命令及实际结果、提交哈希、未覆盖场景。执行 `npm --prefix frontend run verify`；在仓库契约虚拟环境执行 `scripts/validate_contract.py`，并检查 git diff。STATUS 基线回填为已存在且在 HEAD 祖先链上的提交，避免再次触发超过 3 个提交的基线守卫。

发布/已读等浏览器真实模式测试会写入数据，按项目约定先获得对应测试环境授权；不要因本方案而操作现有数据库或启用外部模型。后端自动化使用隔离临时数据库，其结果不能冒充页面真实联调证据。
