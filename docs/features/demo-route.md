# 演示路线（12 分钟）

用两次连续体验展示「读讲义、练习、自测、巩固」和「布置作业、批阅、反馈、跟进」。个人和学校使用独立浏览器会话，学校学生从入班到收反馈使用同一个账号。

## 1. 演示前准备

- 使用本地真实模式，浏览器统一打开 `http://127.0.0.1:4173`。首次运行和账户初始化见 [项目启动说明](../../README.md)。
- 在演示环境配置 `CHECKS_ENABLED=true`，启动前准备 Web 判题镜像。从仓库根目录执行 `docker build -t lms-web-check:1 backend/check-runner`。以独立试跑账号确认个人首题能完成检查，演示时另注册新账号。
- 登录演示教师账号，预建一个独立演示班。发布一章 HTML 讲义，创建「文档结构」知识点并关联该章，再发布一题课堂作业和一道后续巩固题。两题都关联这个知识点，截止时间留在演示之后。最后生成仍在有效期内的邀请码。
- 备用路线可以用 `node scripts/demo-seed.mjs` 准备班级。种子数据中 `demo.s1` 已收到评价，`demo.s2` 已有提交待批阅。演示备用路线时，从 `demo.s2` 的待批阅记录接着做，发布后切到同一账号收反馈。要展示现场注册和新提交，使用独立演示班和新学生账号。
- 提前确认 AI 供应商状态。外部供应商关闭时可展示平台的降级提示；使用本地确定性测试回复时，明确标注为本地测试，不当作真实模型输出。屏幕只展示演示数据，凭据保留在本机配置中。

## 2. 个人自学（约 5 分钟）

1. 在独立窗口从登录页进入「自助注册」，选择「个人自学」。注册后直接进入学生首页，并获得默认的 Web 开发课程。
2. 从「我的课程」打开第 1 章「HTML 基础」。点击侧栏「HTML 文档结构」定位到讲义，在同一章打开「示例练习：补全首页的移动端声明」。
3. 进工作区，保留初始模板并运行「自动检查」。预期通过 **2/3** 项，移动端声明未通过。说明「运行」用于预览，「自动检查」会按当前保存版本判定。
4. 点击「AI」，描述窄屏表现和实际尝试，勾选「附上当前工作区」后发送。供应商可用时，展示与当前版本相关的排错方向和课程引用；供应商关闭时展示页面的实际降级提示，再返回刚读过的讲义继续。可用示例提问「标题和提示文本都通过了，手机上页面还是整体缩小。我应该先验证文档哪里？」
5. 按讲义修正视口声明并重新检查。预期当前版本通过 **3/3** 项。沿「下一题」进入同一章的 HTML 迁移练习，说明如何把文档结构和视口规则用到另一页。也可打开「学习记录」核对首题已通过和后续练习入口。

## 3. 学校教学（约 6 分钟）

1. 教师打开预建的教学班，展示发布的章节、课堂作业和邀请码。新窗口注册学校学生，用邀请码入班。从章内作业或首页打开课堂作业。
2. 在工作区编辑，点击「提交作业」并填写反思。教师进入「作业管理与批阅」，找到该学生的最新提交。
3. 教师填写量规得分和评语，给「文档结构」选择「需要练习」并说明具体原因，发布反馈。学生用同一会话打开「消息通知」→「查看评价」，核对作品快照和公开评语。若已准备同知识点且仍可提交的巩固题，评价旁的「下一步」会直接链接到对应练习；没有匹配建议时，可进入本班学习记录。
4. 教师打开班级「学习分析」，查看近期学习事件和知识点掌握分布。在「各知识点明细」找到「文档结构」，点「查看需要练习的学生」，再进入该学生的学习记录。名单按班级成员分页，在当前页没看到目标学生时可以翻页。
5. 收尾时说明三个判断各有证据。自测反映个人当前保存版本，教师评价形成课堂知识点证据，后续建议关联可访问的课程资源或练习。

## 4. 故障兜底

| 现象 | 处理 |
| --- | --- |
| 登录或页面提示服务不可用 | 核对 Docker、后端 `/health/ready` 和前端地址，服务就绪后刷新。 |
| 自动检查不可用 | 检查演示环境的判题开关和 Web 判题镜像。未得到结果时展示预览和讲义，说明现场未完成判题。 |
| AI 给出降级提示 | 展示实际状态，再回讲义完成练习。 |
| 邀请码无效 | 教师生成新的有效邀请码，同一个新学生完成余下课堂流程。 |
| 没有「需要练习」结果 | 核对课堂作业与知识点的关联和评价是否已发布。 |
| 现场未留下新提交 | 使用种子班的 `demo.s2` 待批阅提交，从批阅接着走。 |

本地验收和功能范围见 [当前状态与交接](../STATUS.md)。演示结束后可运行 `scripts/Stop-Demo.ps1` 停止本地前后端。
