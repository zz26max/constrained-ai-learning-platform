# 功能地图与受限式 AI 辅导设计

本文件回答两个问题：**平台现在有哪些功能、各自到什么程度**；**受限式 AI 辅导的五层机制现在做到哪、下一步怎么深化**。状态以契约为准：`verified` 有真实页面或联调证据，`implemented` 有生产实现与自动化测试，`未做` 表示尚未实现。

## 3. 受限式 AI 辅导设计（深化）

### 3.1 设计原则

1. **不懂就给方向，不替学生写**：任何一层都不得产出可直接提交的实现。
2. **服务端说了算**：提示层级、可用模式、上下文范围、引用、预算都由服务端决定，客户端只提交动作与内容。
3. **可解释、可复现**：每次交付都留痕（政策版本、层级、回退原因、用量、引用），既能审计也能做实验。
4. **失败要诚实**：模型不可用、预算不足、政策回退必须区分，回退时给固定模板而不是伪装成个性化回答。

### 3.2 五层机制现状

| 层 | 实现要点 | 现状 |
| --- | --- | --- |
| L1 课程知识库 | 按作业知识点/章节召回本班 `resources`；无关联时回退本班全部 active 讲义；关键词打分取前 2，片段截 900 字；回复带 `citations` | 已实现 |
| L2 分级提示 | `concept` 固定第 1 层；`next_hint` 最高层 +1；超过 `maxHintLevel` 返回 `HINT_LIMIT_REACHED`；第 2 层起要求尝试描述 | 已实现 |
| L3 静态分析 | 生成前读最近一次 `assignment_checks`，把未通过规则压成 `checkFindings`（规则 id、选择器、期望值） | 已实现 |
| L4 基于错误的反馈 | `checkFindings` 的每条失败规则映射成动作指令（`feedbackFocus`）；回复必须点名规则/选择器并带问句，否则视为不合格并回退 | 已实现（代码级校验） |
| L5 记录与拦截 | 跨会话历史、12k 披露上限、意图/敏感词/代码检测、固定模板回退、预算与频率 | 已实现 |

### 3.3 检索与引用（L1）

- **候选**：作业知识点关联的资源 → 否则作业所在章节 → 否则本班全部 active 资源（最多 20 条）。
- **打分**：问题 + 尝试描述 + 作业描述；英文按词、中文按二元组；标题命中 ×3、正文 ×1；同分按标题稳定排序。
- **输出**：最多 2 条资料进上下文，每条 900 字窗口；`citations[{resourceId,title}]` 随回复返回；回退与过期为空数组。
- **边界**：只读本班资源，不跨班、不读参考答案、不向量化（确定性优先，便于复现）。

### 3.4 L4 深化：把“错误”变成“可验证的下一步”

目标：反馈不是复述检查项，而是**按错误类型给出不同的引导动作**。

| 错误类型（来自 checkFindings 或工作区） | 反馈动作 | 不该做的事 |
| --- | --- | --- |
| 结构缺失（缺 doctype / 标签未闭合） | 让学生先在浏览器里看渲染结果与 DOM 树 | 直接给补齐后的整段 HTML |
| 样式未命中（选择器不存在 / 特异性被覆盖） | 让学生用开发者工具检查元素是否匹配规则 | 直接给新选择器 |
| 布局溢出（min-width / box-sizing / 100vh） | 让学生量出容器与子项的实际宽度 | 直接给修复后的 CSS |
| 事件未生效（脚本时机 / 选择器为 null / 冒泡） | 让学生先确认控制台报错与执行时机 | 直接给完整脚本 |
| SQL 语义错误（NULL 比较 / 缺 GROUP BY / 笛卡尔积） | 让学生先描述预期行数与实际行数 | 直接给正确 SQL |

实现方式（2026-11-09 已落代码）：`TutoringFeedback` 把失败规则按 `check` 类型（`exists`/`text`/`css`）翻译成动作指令，写进上下文 `feedbackFocus`；同时对模型输出做一次校验——**必须命中规则 id 或选择器，且包含问句**，否则按一次受控重生成处理，仍不合格回退固定模板。这样“先反问、给方向”从提示词约定变成了可执行的判定。

### 3.5 拦截与回退（L5）

- 输入：索要完整答案、角色扮演、忽略规则、注入指令 → 规则拦截。
- 输出：代码围栏、`<script>`/`function(`/SQL 关键写法、完整实现、敏感信息 → 拒收；至多一次受控重生成，仍不合格给固定模板。
- 回退语义：`status=fallback` + `fallback_reason`，不伪装成模型回答；模板内容固定，便于统计与审计。

### 3.6 消融开关（支撑实验）

`AI_ABLATION_DISABLE=static,intercept_input,intercept_output,graded_hints,rag`（默认空）：

| 取值 | 关闭的层 | 可观测变化 |
| --- | --- | --- |
| `static` | L3 | `checkFindings` 恒空 |
| `intercept_input` | L5 输入拦截 | 注入/索答文本直达模型 |
| `intercept_output` | L5 输出拦截 | 代码块可被交付 |
| `graded_hints` | L2 | 请求层级强制为 1 |
| `rag` | L1 | 不召回，`citations` 恒空 |

### 3.7 待深化项（按顺序）

1. **L4 显式映射**：把 3.4 的表落到代码，并对输出做“点名规则 + 验证动作”校验。
2. **引用可见性**：前端把出处做成可点击的资料链接（现在只显示标题）。
3. **共性问题 → 知识点**：把教师端共性问题映射到知识点，补齐分析闭环。
4. **检索质量**：命中率不足时再考虑按章节加权或向量召回。
5. **部署演示**：Docker Compose 一键起（数据库 + 判题镜像 + 前后端）。

## 4. 已知缺口

| 缺口 | 影响 | 计划 |
| --- | --- | --- |
| ~~个人模式只有讲义、没有练习~~ | 个人自学者无法走完「学 → 练 → 判 → AI」 | **已补（V18）**：个人课程自带 2 份示例作业与默认 AI 政策 |
| 教师注册建班固定叫「我的班级」 | 演示观感一般 | 后续允许填班级名 |
| 无「个人 → 学校」升级 | 自学者有老师后需重新注册 | 优先级低 |
| 实验三件（运行器 / 判定 / 结果） | 论文③④⑤无数据 | 见实验方案，暂缓（用户决定先做平台） |
| 软著材料包 | 交付清单缺一项 | 暂缓 |
| 学习分析数据薄（证据 2 条、求助 0 条） | 看板演示偏空 | 用 `demo-seed.mjs` 造数据 |
| 教师端求助页面未做真实走查 | 功能有但无页面级证据 | 后续补一次浏览器验收 |
| 未部署 | 只能本机演示 | 作为加分项排期 |
