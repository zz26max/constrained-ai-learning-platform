只修改 frontend 独立高校预览、现有 DESIGN.md 与允许更新的 STATUS.md。正式 features 页面、后端、数据库、API契约、教师端及高校演示数据源未改。未引入依赖、图片、字体、装饰动效、虚构掌握率或时长。

## 3. 三页面设计变化与组件说明

| 位置 | 决定 | 信息价值 |
| --- | --- | --- |
| 首页焦点 | 保留深蓝主任务，学科缩写单色反白，进度/资格文字明确分开 | 保持下一步操作的视觉中心，不堆彩色标签 |
| 首页近期任务 | 保留精确截止分组，细线串联任务，课程使用轻量缩写/名称 | 同组截止只出现一次，各任务与操作独立 |
| 首页最近课程 | 小型学科图形、分类/课程标题、真实开放章节分段、对应章节动作 | 与课程页有视觉关联，但不复制完整卡片；去掉同一章节的重复位置描述 |
| 首页反馈/公告 | 中性32px分数、明确课程关联、完整反馈展开与未读提示 | 分数只代表本次作业，不与主任务争夺注意力 |
| 我的作业 | 学科身份进入课程列；日期与北京时间分两行；进度、时间、资格分别标明 | 保持完整资格查询后优先分组、截止排序和分页，不用学科色表示紧急程度 |
| 作业手机布局 | 筛选并列，日期和操作同行，状态随后；长标题自然换行 | 减少旧规则导致的多余行，保留44px操作高度 |
| 消息通知 | 五类事件图形配类型文字，未读点/文字/字重并用，独立课程关联 | 能先判断事件，再读标题摘要；类型色只用于小图形，不整行彩色背景 |
| 消息交互 | 保留全文展开、详情入口、显式标读和分页 | 展开不自动标读，不合并消息，不隐藏重要事件 |

新增最小组件：SubjectIdentity（已有mark映射+课程名）、DeadlineStamp（北京时间日期/时刻）、IntegratedTaskStatus（既有状态与详情资格分层）、MessageTypeGlyph（统一线宽的五类图形）。CountProgress、SubjectGlyph、chapterEntry、submissionLabel继续复用，没有另造业务状态机。

共享学科规则：JAVA/WEB蓝，DB/DSA青绿，NET/SE灰紫，AI/MEDIA赭金；未知mark中性，不根据标题猜分类。消息仅在明确offeringId能关联课程时显示学科身份，不给无关联或多课程内容强行分类。事件类型图形与学科身份是两个独立维度。

排版：页面标题28px/手机26px、模块20px、内容14–16px、辅助12–13px；少量缩写和状态角色11px。正文行高1.65–1.8。操作至少44px，焦点3px。普通文本以中性色建立层级，只有实际补交资格用暖色。容器用于真实分组，任务与消息维持分隔线列表。

现有 `frontend/DESIGN.md` 增补候选规范；旧正式规范不变。未采用渐变、图片封面、统计卡片堆叠、进度圆环或新的品牌口号。

## 8. 发现、修正与限制

| 问题/失败 | 处理与剩余边界 |
| --- | --- |
| 消息新增课程行与旧网格行号冲突，操作跑到摘要之前 | 明确内容与操作行号；重新查看手机原图及展开操作通过 |
